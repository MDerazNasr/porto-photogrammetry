TEN-STEP PLAN
1. First I'll clone Augenblick with its VGGT and Neuralangelo submodules to reproduce one complete run. Then i'd pin the Python, PyTorch, CUDA, and library versions in Docker (In case they require different environments) . Next, I would run the pipeline on a DTU benchmark scene using PACE and save the input images, commit hashes, configs, camera estimates, mesh, runtime, and GPU memory usage. Since the repo's testing and benchmark sections might be incomplete, I would add a pytest suite that verifies image loading, camera export, and mesh generation before changing the reconstruction methods.

2. I would build a benchmark using a development subset of 10 DTU scenes because DTU provides calibrated cameras and structured reference scans. I would also use a pilot set of about 20 museum specimens selected with the Museum team. For each museum specimen, I would capture about 72–120 images across several elevations with 60–80% overlap and record physical measurements. The scale target would recover world dimensions, and the color chart would provide a reference for evaluating color accuracy.

3. Next, I would add automated image preprocessing and input quality checks with a Python preprocessing stage built with OpenCV, ExifTool, and the Colour Science library. This stage would correct lens distortion, apply color calibration, resize images, and remove the background. Then I test Segment Anything 2 for object masks and inspect its performance on thin structures such as legs and bone edges. The preprocessing stage would also detect capture problems before reconstruction begins by measuring blur with Laplacian variance, detecting overexposed pixels from the image histogram and verifying that each specimen is visible from enough viewing angles.

4. Then, I would compare VGGT for camera reconstruction. I would run 3 camera conditions on the same image set (COLMAP, frozen VGGT, and VGGT followed by bundle adjustment). I would then repeat the comparison with 24, 48, and 96 input views. On DTU, I would measure camera rotation error, translation error after scale alignment, reprojection error, registered image percentage, runtime, and peak VRAM usage. On the museum data, I would compare reprojection error, cross consistency, and reconstruction failure rate. This experiment would show whether VGGT reduces runtime without introducing camera errors that affect later stages.

5. Next, I would build and test the interface between VGGT and Neuralangelo by writing a Python conversion tool with NumPy and pycolmap that converts VGGT outputs into the camera and scene into the expected format. The conversion would normalize the scene bounds and recover metric scale from the scale target. I'd also write tests that project 3D points into each camera, convert the cameras through the full pipeline, and confirm that the coordinates remain correct after conversion.

6. After that I'd reconstruct the neural surface with Neuralangelo because it is designed to recover dense surfaces and fine detail from multi-view RGB images. I'd start with the published configuration and use the VGGT or COLMAP cameras selected in the previous experiment. I would reserve 20% of the images as held out views and train on the remaining 80%. Then during training, I would record training time, GPU memory usage, convergence, and mesh quality and run Instant-NGP as a fast appearance baseline.

7. After reconstruction, I would extract the Neuralangelo signed distance field as a mesh with Marching Cubes. Then I'd use Open3D and Trimesh to remove disconnected background components and compute surface normals. I would log every cleanup operation so the pipeline never changes geometry without recording it. Then, I would generate UV coordinates with xatlas and bake textures from the calibrated source images with Blender's Python API. The final output would include a full-resolution PLY or OBJ for analysis and a GLB with a 4K or 8K texture for web visualization and CGI.

8. Next, I would define and measure museum grade quality by evaluating geometry, color, and scientific usefulness. On DTU and any museum specimens with reference scans, I would compute surface accuracy, completeness, Chamfer distance, F-score, and normal consistency with Open3D or PyTorch3D. I would also compare digital landmark distances against the caliper measurements. As an initial acceptance target, I would aim for < 2% mean error in physical measurements, based on the COPIS natural history digitization study. Also I'd evaluate rendered views with PSNR, SSIM, and LPIPS and use CIEDE2000 to compare reconstructed colours against the reference images.

9. Next, I would run ablation studies and document failure cases with Hydra configuration files and MLflow to track experiments across the number of images, image resolution, camera method, and surface reconstruction method. The ablations would compare different numbers of input views, image resolutions, COLMAP versus VGGT versus VGGT with bundle adjustment, and masks enabled versus disabled. I would repeat neural reconstruction runs with three random seeds on a smaller representative subset. I would report the mean and bootstrap confidence intervals and label failures by cause, including incorrect camera poses, missing thin structures, reflective surfaces, weak texture, poor masks, incomplete image coverage, and inaccurate color. This will help discern whether the pipeline needs a model improvement/ better image capture.

10. Finally, I would package the selected workflow into a repeatable pipeline with Python and Snakemake. Each stage would have defined inputs and outputs and GPU intense stages would run on PACE, while lightweight validation checks would run in GitHub Actions. I would store the complete environment in a container and test it on a clean Linux machine. For each specimen, the pipeline would produce the mesh, textures, camera settings, scale information, configuration files, and other key outputs. Any failed quality checks would stop the pipeline and report what needs to be recaptured or reviewed. I would finish by testing the complete system on a group of museum specimens and use the feedback to define separate preview and museum quality presets.
